## 一、聊天双向收不到 —— 根因找到了：兜底通道解码 off-by-one

**症状**：2P 发几十条 1P 最多看到一条；1P 发几十条 2P 一条都看不到。

**根因（实证复现 + 修复 + 回归验证）**：聊天有两条通道——
- 原生 chat 中继（服务器 v51+）；
- **输入通道兜底**（服务器 <v51 时客户端自动把聊天编码成"负帧号 input"）。

兜底通道的**解码有一个致命 off-by-one**：编码端把第 i 片存在键 **i+1**（1-based），
解码端却用 **buf[i]**（0-based）取片——`buf[0]` 永不存在 → "缺片丢弃" →
**旧服务器上每一条兜底聊天都在组装时被静默扔掉**。这就是"发几十条一条都看不到"。

**怎么证实的**：把仓库里真实的 `NetplayController.kt` + `BattleNetplay.kt`
编译成 JVM 测试体，连到真实编译的服务器上跑双人 60Hz 对战 + 双向各发 40 条聊天：

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| v58/v59 服务器（原生 chat） | 40/40 ✓ | 40/40 ✓ |
| **旧服务器（<v51，走兜底通道）** | **0/40 ✗ 全丢** | **40/40 ✓** |

一行修复：`buf[i]` → `buf[i + 1]`。**从此无论服务器多旧，聊天都能送达。**

**额外加固（同样重要）**：
1. **聊天历史不再丢**：消息此前只存在界面临时状态里——游戏中开一次菜单
   （暂停/设置/编辑器），聊天面板历史就清零，看起来像"消息丢了"。现在
   消息留痕在控制器里，开关菜单/面板历史都在（上限 50 条）；
2. 服务器版本升到 **59**（协议字节不变）：部署新服务器后，两边聊天面板
   顶部都应显示"服务器版本 59"。

## 三、虚拟按键手柄映射 —— 补上实体手柄的摇杆轴（PS2 最明显）

**排查结论**：PS2 的按键映射表本身是全套的（16 键 + 双摇杆，屏幕按钮、
按键映射、显隐开关都齐全）。真正缺的是：**实体手柄的模拟摇杆轴从来
没有任何监听**——只有按键事件（KeyEvent）走数字位，`AXIS_X/Y`（左杆）、
`AXIS_Z/RZ`（右杆）被直接丢弃。所以蓝牙手柄插上后，PS2/3DS/NGC-Wii/
WiiU/DC/PSP/Switch 的**摇杆完全不动**——这就是"映射缺少很多"的体感。

**修复**：
- 新增实体手柄轴监听（GenericMotionEvent），与屏幕虚拟摇杆**走同一条
  平台路由**（PS2 双杆、3DS CirclePad/C-Stick、NGC 主杆/C 杆、WiiU 双杆、
  DC、PSP、Switch）；
- 摇杆死区带滞回（12% 触发 / 6% 释放——轻推即动、回中不抖）；
- 顺带补了 **AXIS_HAT 帽轴十字键**（部分手柄十字键以轴上报而非按键——
  这类手柄连方向键都不动的问题一并修复），与按键同一条联机转换链路。

## 四、追赶提速

接入者重放距离 = 最新帧 − 服务器缓存快照帧。三项提速：

1. **房主快照上传间隔收紧**：6/10/15s → **3/5/8s**——快照更 fresh，
   接入者要重放的帧数直接砍半以上（追赶耗时的主要成分）；
2. **追赶尾距 90 帧 → 60 帧**（1.5s → 1.0s）：尾段受实时输入 60Hz 到达率
   限制无法加速，是硬下限，收紧直接省 0.5s；
3. **进度显示速率 + 剩余时间**："1234/5678 · 245f/s · 剩9s"——追赶在满速
   快进（重放速率远超 60fps）时你看得见它在动。

## 五、Android 17 多点触控

虚拟按键的触摸处理三处鲁棒化（任何新版系统上都更稳）：

1. **弃用 awaitFirstDown**：它一次只返回一个按下，同一事件里其余手指的
   按下被整包吞掉（双指极快同落时第二指永久丢失）→ 改为自管事件循环，
   逐事件逐变更处理，一个都不吞；
2. **弃用整数计数**：指针计数一旦漂移提前归零，内层循环提前退出，已按住
   手指的全部事件被无视——表现正是"多点触控失灵、必须全部松手才恢复"。
   改为**按下指针 id 集合**（重复/未知事件都不会漂移）；
3. **按下/抬起/移动判定全部忽略"消费位"**：新版系统上系统手势/上层组件
   消费事件后，旧判定恒 false（按下被吞 = 该指失灵；移动被吞 = 搓招卡死）。
   本覆盖层是游戏输入终点，读原始事件是正确语义。

## 一、三国战记3HD：不再 12 秒杀进程（按你的要求重做）

你说得对：**这游戏本来就要加载一段时间，12 秒就报错肯定不行，而且要保证
核心真的在运行它**。v57 的帧看门狗是"12 秒内帧号必须 >0"的硬切，会误杀
还在解压/引导的核心。v58 改成「智能启动监护」：

**先搞清核心为什么要加载这么久**（对 libpgm3.so 做了二进制级核实）：
- kov3hd 启动有 **staged startup movie（分段开机影片）**——二进制字符串
  "original decoder selects an actual staged startup movie"，模拟真机
  逐步加载的过程；
- CHD 光盘镜像是 **LZMA 压缩**（CHDR_LzmaDec_* 全套符号），首次启动要
  解压 + 预缓存，大镜像 + 慢存储上就是分钟级；
- 核心有完整的状态机文案（二进制里提取出"等待启动/游戏尚未启动/游戏运行中
  /游戏已停止"等中文状态串）——这就是"核心真的在运行"的判据。

**新监护逻辑（Pgm3Engine.watchdog）**，每 250ms 轮询三个"活着"信号：
1. **帧号 > 0** → 渲染已起跑（最终成功条件，出现即通过）；
2. **核心状态文本变化**（nativeStatus："等待启动"→…→"游戏运行中"）→
   状态机在推进；
3. **interactive.log 大小增长** → 核心在写日志。

**超时矩阵**：
- 完全无活动：最多等 **90 秒**（首帧上限）；
- 只要有活动（状态/日志在变）：一直等到 **180 秒**总限，绝不提前杀；
- **静默判死 30 秒**：自最近一次活动起，三个信号全无变化——这才是"核心
  真死了"（跟"核心在加载"的区分线）。真死了也不可能自己活过来，此时才停核。

**错误快速失败**：状态文本/日志出现明确失败语义（"Unsupported CHD"、
"无法打开/不存在/校验失败"、"EGL window mode target is missing"等，
全部来自二进制里实际存在的失败字符串）→ 3 秒确认后立即报错，不傻等。
失败时给出：失败原因 + 最后核心状态 + interactive.log 尾部 6 行。

**等待期间你能看到什么**（不再是无解释黑屏）：
- 启动屏显示：「正在启动三国战记3HD：核心状态「等待启动」，已等待 45s，
  日志 12KB」+ 一行黄字提示「首次启动需解压光盘镜像，可能要 1~2 分钟」；
- logcat 每 2 秒一条进度（`adb logcat -s Pgm3Engine` 可看）；
- 核心每次状态切换都会打一条（`核心状态 → "游戏运行中"（+37s）`）。

> 一句话：**只要核心真的在跑，等多久都陪它；只有确认它死了才报错，且
> 报错必带真实原因。**

# 修复说明 v64（三国战记3HD rc=0 秒退最终根治）

参考基准：afbn-release-64.apk（filebin.net/nesstation-fbn）+ libpgm3.so
二进制逐指令反汇编（capstone 全量扫描 30MB 可执行段）。本次结论全部来自
二进制证据链，非猜测。

---

## 一、最终根因（本次二进制级坐实）

用户 v63 截图（interactive.log 尾部）给出的完整证据链：

```
CHD_MOUNT original_zip=...kov3hd.zip original_chd=...kov3hd_m105.chd
          source=original_only hunks=35        ← CHD 正常挂载
PASS ARM32_AOT_LOADING_BAR / NONLOCAL_JUMPS / PUTCHAR / WRITE_GATE
PASS ARM_EABI_DIVISION / ARM_EABI_FLOAT             ← AOT 自检全过
CONSTRUCTORS_RESULT completed=13 planned=13          ← guest 构造函数全跑完
MAIN_AOT_PROGRESS pc=60001240 instructions=98 stop=1 ← 主程序仅执行 98 条指令
AFBN_SURFACE generation=2 attached=1 frames=0        ← Surface 正常附着
FRAM_CHECKPOINT written=1 mode=frontend_exit
AFBN_GAME_SESSION stopped=frontend_request original_draws=0
                                                     ← ★ 被前端主动停止
```

核心本身完全健康（挂载/自检/窗口全部正常），会话是被 `nativeStop()`
主动杀掉的。libpgm3.so 反汇编结论：

1. `nativeStop`（0x8001a0）向全局停止标志 **0x24bb040 写 1**；
2. **全 30MB 可执行段只有这一条指令写 0x24bb040**（find_writers.py 全量
   扫描；.rela.dyn 重定位表与字面量池亦无该地址）—— **没有任何代码清零它**。
   nativeRun 入口重置了 0x24bb020/28/2c/30/48/4c/60、0x24bafe0~f8 一整片
   标志却刻意跳过 0x24bb040 ——「粘滞直到进程死亡」是核心的设计
   （参考实现 afbn 的语义 = 一次会话一个进程，退出即结束进程）；
3. 会话主循环每帧开头读该标志（0x7fd1c8：置位 → 立即退出循环）→
   nativeRun 以 rc=0 返回，状态写【短版】"游戏已停止"、
   interactive.log 落 `AFBN_GAME_SESSION stopped=frontend_request`。

而本项目 `Pgm3Engine.cleanup()` 在【每次 loadRom 开头】都无条件调
`nativeStop()` → 第一次进游戏前标志就已是 1 → 会话刚起步（主程序
98 条指令处）即被"前端请求"停止 → rc=0 零帧。v52~v63 全部命中：
v61 及以前被「loadRom 等首帧」死锁掩盖成 150s 卡"解压chd"；v62 修好
窗口死锁后，真正的根因（粘滞停止标志）暴露成 rc=0 秒退。

## 二、修复（v64）

无法从 Java 清零该标志（二进制无此入口），对齐参考实现"一次会话一个
进程"语义：

1. **`Pgm3Engine.cleanup()`**：只在【确实启动过会话】（started=true）时
   才调 `nativeStop()`——首次启动前不再污染标志，进程内第一局必活；
2. **粘滞标志跟踪**：一旦调过 nativeStop（用户退出游戏 / guard 启动失败
   收尾），同进程内后续 nativeRun 都会被秒杀 → 置
   `Pgm3Engine.needsProcessRestart`，loadRom 直接返回 false；
3. **自动重启直达游戏**（EmulatorScreen + NesApp）：
   - EmulatorScreen 三处入口（直读分支 / SAF 分支 / loadRom 失败竞态
     兜底）检测 needsProcessRestart → `restartAppToOpenGame(context,
     game.id)`：携带 `nesstation_auto_open_game` extra 的启动 Intent
     （NEW_TASK|CLEAR_TASK）+ 结束当前进程；
   - NesApp（Phone/Tv 两套 NavHost）启动时消费该 extra → 直接导航到
     目标游戏并清除 extra。
   玩家体验：第一次点 kov3hd 正常进游戏；退出后再点 = 应用秒重启并
   直接回到游戏 —— 与参考实现"退出游戏即结束进程"的行为完全一致。
4. 顺带修复：guardFail 的 nativeStop 同样置位 needsProcessRestart ——
   用户修好 CHD/ROM 后重进，自动重启再启动，不再被上一次失败的标志毒杀。

涉及文件：
- `app/src/main/java/com/nesstation/app/core/engine/Pgm3Engine.kt`
  （cleanup 条件停核 + needsProcessRestart + loadRom 守卫）
- `app/src/main/java/com/nesstation/app/ui/emulator/EmulatorScreen.kt`
  （restartAppToOpenGame + 三处守卫接入）
- `app/src/main/java/com/nesstation/app/ui/NesApp.kt`
  （Phone/Tv NavHost 消费 nesstation_auto_open_game extra）

## 三、验证要点（装机后）

1. 首次点《三国战记3HD》：应正常进游戏（interactive.log 出现
   `AFBN_SURFACE ... frames>0`，不再有 `instructions=98` 秒退）；
2. 游戏内退出 → 再次点该游戏：应用自动重启（黑一下）→ 直达游戏 → 正常；
3. 故意改名 CHD 触发启动失败 → 修好文件名 → 再进：同样自动重启后正常；
4. 其它核心（FBNeo/PS2/Switch…）行为不受影响（改动全部限定在 PGM3 路径）。

# 修复说明 v65（kov3hd 按键互换 + 二次启动提速 + 仿电视机滤镜 + 对战同步语音）

全部修改基于最新源码仓库（v64 之后）实测反馈：

1. 《三国战记3HD》按钮 A 和 B 反的，C 和 D 也是反的；
2. 首次运行后下次启动应该很快才对，但还是需要加载很久；
3. 只有这一个游戏不支持仿电视机滤镜；
4. 新需求：对战平台对战时加入同步语音系统，打开后可以随意语音聊天对战，
   按钮放在聊天按钮旁边，未开启是灰色、开启是亮色。

## 一、kov3hd 按钮互换修正（A/B、C/D）

### 根因

本项目街机虚拟手柄 UI 的按钮 A/B/C/D 经 `arcadeToLibretroLayout`（EmulatorScreen.kt）
编码为 libretro JOYPAD 位：

| UI 按钮 | libretro 位 | 位值  |
|---------|-------------|-------|
| A（街机键1）| JOYPAD_B | 0x001 |
| B（街机键2）| JOYPAD_A | 0x100 |
| C（街机键3）| JOYPAD_Y | 0x002 |
| D（街机键4）| JOYPAD_X | 0x200 |

这是 FBNeo 等核心通用的街机惯例（其他游戏按键全部正常，反证转换无误）。

而 `Pgm3Engine.toMcuBits` 把两对位的 MCU 目标写反了：

- bit8（UI B）→ 0x020 攻击1、bit0（UI A）→ 0x040 攻击2 —— UI 按 A 出 B 键动作；
- bit9（UI D）→ 0x080 攻击3、bit1（UI C）→ 0x100 攻击4 —— UI 按 C 出 D 键动作。

### 修复

`Pgm3Engine.toMcuBits` 按 UI 键序重新对齐：UI A→攻击1(0x020)、UI B→攻击2(0x040)、
UI C→攻击3(0x080)、UI D→攻击4(0x100)；方向 / Start / 投币（Select 下沿）不变。

涉及文件：`app/src/main/java/com/nesstation/app/core/engine/Pgm3Engine.kt`

## 二、二次启动提速（退出重进不再"加载很久"）

### 根因

v64 确认 libpgm3 的停止标志 0x24bb040 是"粘滞"设计：只有 `nativeStop` 写 1、
全 30MB 可执行段无任何清零代码 → 进程内一次会话后无法再开会话 → v64 的兜底
是【重启应用直达游戏】。但重启进程意味着：

- 39MB 的 libpgm3.so 重新加载 + 动态重定位；
- 运行时固件重新校验、核心全部状态冷启动；
- CHD 解压 / AOT / 构造函数全部重来。

→ 退出重进 = 每次都完整冷启动 = "还是需要加载很久"。

### 修复（v65）：进程内清零粘滞标志，免重启应用

新增 `Pgm3Engine.clearStickyStopFlag()`（loadRom 的 needsProcessRestart 分支
先尝试清零）：

1. `/proc/self/maps` 找 libpgm3.so 首个偏移 0 的映射段 → 加载基址；
2. 运行时地址 = 基址 + 0x24bb040（readelf 核实：位于最后 LOAD 段
   0x24ba3c0 + MemSiz 0x5f60 的 .data/.bss 区间内）；
3. 经 `/proc/self/mem` seek 到该地址原位写 4 字节 0（自进程写自身内存，
   无需任何特权），先读后写 + 读回验证。

清零成功 → 不再重启应用，直接拉新会话 —— so 已加载、系统页缓存全热，
二次启动显著提速。安全兜底（绝不比 v64 差）：

- 清零任何一步失败（maps 无 so / mem 不可读写）→ 回退 v64 重启应用流程；
- 清零成功但会话仍秒退（rc=0 无首帧）→ worker 失败路径重新置
  needsProcessRestart，下次自动降级回重启流程。

涉及文件：`app/src/main/java/com/nesstation/app/core/engine/Pgm3Engine.kt`

## 三、仿电视机滤镜支持三国战记3HD

### 根因

PGM3 与 PS2/PSX/WIIU/Switch 同为「直绘 Surface 的推模型核心」（核心自持
EGL/GL 画到传入的 Surface，无帧回读）。旧版视图分支里 tv 系滤镜的画布路径
（TvCurvedGameView）是拉模型 —— 只支持"无 Surface 时每帧回写 frameBuffer"
的引擎。PGM3 落进去拉不到帧 → 选「仿电视机」无效/黑屏。

### 修复

PGM3 加入已有的 Ps2CurvedView 弧面中转分支（PS2/PSX/WIIU/NSWITCH 同一条、
全部实测可用的成熟机制）：

```
libpgm3 ──GL 直绘──▶ SurfaceTexture（离屏真实 Surface，nativeSurface 契约不变）
                          │ updateTexImage
                          ▼
        Ps2CurvedView GL 线程 ──nsCurve 桶形凸起──▶ SurfaceView 上屏
        （+ 扫描线 / 径向暗角 / 玻璃高光，与其他核心观感一致）
```

- 触发条件：`engine is Pgm3Engine` 且滤镜为 tv / *_tv 系；
- PGM3 的 setSurface / onSurfaceChanged / nativePause 时序由引擎自身保证
  （v62 起 worker 等 Surface），无需额外接线；
- EGL 初始化失败 → ps2GlFailed → 回落普通 SurfaceView（无凸起但绝不黑屏）。

涉及文件：`app/src/main/java/com/nesstation/app/ui/emulator/EmulatorScreen.kt`

## 四、对战同步语音系统（新功能）

「打开后可以随意语音聊天对战」—— 全双工实时语音，走既有 TCP 中继，
游戏与对战状态不受任何影响。

### 4.1 协议（客户端 + 服务器）

新消息 `type=voice`（与聊天 type=chat 同构，服务器只转发不编解码、不落盘）：

```
-> {"type":"voice","data":"<base64 PCM16 音频帧>"}
<- {"type":"voice","data":"...","from":"名字","slot":1..4,"spec":bool}
```

音频格式：PCM16 / 单声道 / 16kHz / 40ms 一帧（640 样本 = 1280B → base64
约 1.8KB，~360kbps）。服务器限长 96KB（约 1.5s 音频）防刷流量；未加入房间
发语音回 error 提示（与 chat 同款可诊断性）。

- 客户端 `BattleNetplay.kt`：接口加 `onVoice(from, dataBase64, slot, spec)`
  回调 + `sendVoice(dataBase64)`；handleMessage 加 "voice" 分支。
- 客户端 `NetplayController.kt`：UiListener 加 `onVoice`；netListener 接线
  dispatch 到 UI；新增 `sendVoice()`（断连静默丢帧，不影响对战）。
- 服务器 `server/relay.go`：switch 加 `case "voice"` 转发房间其他成员
  （玩家 + 观战者，与 chat 同语义）。**编译通过 + 全部既有回归测试通过**
  （go test 21.5s ok）；已随包附上重新编译好的 linux 服务器二进制
  （amd64 / arm64），旧客户端收到 voice 消息走默认分支静默忽略 —— 双向兼容。

> 注意：线上服务器二进制需要替换为本次附带的版本（或用 server/relay.go
> 自行重新编译），语音才能真正转发；连旧服务器时仅语音不可用，游戏/聊天无影响。

### 4.2 语音引擎（新文件 VoiceChatManager.kt）

- **采集**：AudioRecord（VOICE_COMMUNICATION 音源 = 系统语音通话处理链），
  40ms 阻塞读帧 → base64 → 发送回调；AcousticEchoCanceler / NoiseSuppressor
  可用即启用（外放对战的回声消除 + 噪声抑制，否则对方会听到回授啸叫）；
  采集线程 THREAD_PRIORITY_URGENT_AUDIO。
- **播放**：USAGE_VOICE_COMMUNICATION + CONTENT_TYPE_SPEECH 流模式
  AudioTrack；单线程阻塞 write 消费队列；抖动缓冲上限 12 帧（≈480ms），
  超出丢最老帧 —— 宁丢帧不加延迟。
- **健壮性**：start/stop 幂等可重入；AudioRecord 构造失败（权限/占用）→
  置 lastError 由 UI Toast 提示，绝不崩溃；接收帧入口 `submitReceived`
  在播放器未启动时直接丢弃。

### 4.3 UI（聊天按钮旁）

EmulatorScreen 聊天浮层（NetplayChatOverlay）：

- 语音按钮在聊天悬浮按钮【正下方】（34dp 圆形，🎤 图标）；
- **未开启 = 深灰半透明底 + 灰白图标；开启 = 亮绿色底 + 白色图标**（用户要求
  "未开启是灰色开启是亮色"）；
- 点击开/关：首次开启弹 RECORD_AUDIO 运行时权限请求（拒绝则提示并保持灰）；
- 开启后顶部 Toast「语音聊天已开启，随时畅聊」，可随时再点关闭；
- 对端语音帧经 UiListener.onVoice 直入播放器（与聊天面板开合无关）；
- 浮层销毁（退出对战/退出游戏）自动 stop —— 杜绝僵尸麦克风采集。

### 4.4 权限

AndroidManifest.xml 新增：`RECORD_AUDIO`（运行时动态请求）+
`MODIFY_AUDIO_SETTINGS`。
